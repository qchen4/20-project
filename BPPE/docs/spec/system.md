# BPPE 系统规格

版本：0.2-draft.1；状态：Draft；批准：未批准。来源：原文 §1～3、§8～10、§13。状态含义见 [文档入口](../README.md)。

## 目的与边界

BPPE 是集成于 MCU SoC 的可编程定点处理 IP，接收规范化 PPG 采样帧，输出血压估算值及质量和状态信息。硬件 result_valid 表示配置的工程质量门控通过，不代表临床准确性。

- **SYS-001｜候选要求**：AFE 传输、LED/PD、TIA、ADC、光学时分调度、SPI/I²C 与源数据转换由 BPPE 外部负责。BPPE 的职责从规范化采样帧开始。
- **SYS-002｜提案**：v1 只提供 32 位 AHB-Lite 从接口，无自主 DMA、AHB Master 或外部 DDR 接口。由 SoC 分配基地址。待决 O-05。
- **SYS-003｜提案**：支持 1～3 路 PPG，每路 24 位无符号规范化样本、32 位采集 tick，并携带有效性和采集元数据。各通道模式可用算法须逐一批准。待决 O-01～O-03。
- **SYS-004｜候选要求**：输入帧原子接受；结果字段原子发布；未确认结果不得静默覆盖。软件访问语义见 REG-004～REG-006。
- **SYS-005｜候选要求**：只有输入质量、数值检查、配置和测量策略全部通过，才能产生有效血压结果。无效结果的压力字段不得作为新测量使用。
- **SYS-006｜提案**：使用单一 HCLK；HRESETn 低有效，释放同步由 SoC 集成侧负责。复位清空 FIFO、处理状态、结果有效/待处理状态和中断。寄存器逐项复位值仍待 O-11。
- **SYS-007｜提案**：输出一个高有效电平 irq，表示使能且未清除的原因。原因保持、W1C 和 ACK 交互待 O-09；idle 信号的外部可见形式待 O-07。
- **SYS-008｜候选要求**：缺样、时间异常、饱和、数值错误、未配置模型、输入/结果溢出必须可观察；不得把过期数据包装为新有效结果。
- **SYS-009｜候选要求**：区分观测时间 T_obs 与计算延迟 T_comp。T_comp 从最后一个必需输入帧被成功接受，到相应结果提交计算；用户总延迟还包含采集、传输和软件处理。
- **SYS-010｜候选要求**：低功耗期间总线协议状态、必要检测逻辑和结果快照不得损坏；算术单元门控须满足恢复及吞吐要求。深度睡眠和状态保持不属于 v1 必选功能。
- **SYS-011｜候选要求**：交付可综合 RTL，完成算法、数值、协议、性能、功耗及 SoC 集成验证。无隐式锁存器；CDC/RDC 例外须有集成依据。FPGA 可作验证平台，不代替目标工艺 PPA。

## 顶层端口提案

输入：HCLK、HRESETn、HSEL、HADDR[31:0]、HTRANS[1:0]、HWRITE、HSIZE[2:0]、HBURST[2:0]、HPROT[3:0]、HMASTLOCK、HWDATA[31:0]、HREADY。

输出：HRDATA[31:0]、HREADYOUT、HRESP、irq。内部 idle 是否另设端口仍待决定，不能据原文“暴露 idle”直接增加顶层引脚。

## 待量化预算

以下均为 TBD，不能作为默认参数：HCLK 频率及范围、每通道采样率与峰值、观测窗口、最大计算周期、输入突发率、最大总线等待周期、FIFO 深度、提交到 IRQ 延迟、唤醒时间、面积和每个合格结果的能耗。

O-06/O-07 的批准记录必须给出数值、单位、工作条件、最坏负载及验证方法。能耗报告须同时给出有效结果率，避免仅降低输出率造成指标失真。

## 系统验收

算法验收由参考数据和批准的使用/标定协议支撑；数值验收由独立的定点误差预算支撑；RTL 验收由逐位比对、协议检查和覆盖率支撑。任何一项的通过不能替代其他项。完整映射见 [验证规格](verification.md)。
